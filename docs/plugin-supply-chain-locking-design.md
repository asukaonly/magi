# Plugin Supply-Chain Locking Design

Status: Implemented — hashed locks, drift CI, and install-time enforcement shipped
Author: brainstorming session 2026-05-31
Last verified: 2026-07-14
Scope: First of three independent plugin-security sub-projects. The other two
(registry-as-authority for the `official` flag; capability declaration +
install consent) were completed in their own spec → plan cycles.

## 1. 背景

Magi 的可选插件住在独立仓 `magi-plugins`,通过 `registry.json` 被 App 拉取,
`git clone --depth 1 --sparse` 到 `~/.magi/plugins/<id>/`,然后安装其 Python
依赖。本设计提出时的安装命令(`backend/src/magi/plugins/installation.py:150-169`):

```
<bundled-python-3.13> -m pip install --target <plugin>/.deps --no-user <deps...>
```

其中 `<deps...>` 来自 `plugin.toml` 的 `dependencies`,是**松版本范围**
(如 `pyobjc-framework-EventKit>=10.0`)。问题:

1. **无版本锁、无 hash 校验**。每次安装抓"当前最新匹配版本"。
2. 上游 PyPI 包被投毒(或某个版本被恶意替换)→ 所有装该插件的用户中招。
3. 用户配的镜像源(清华/阿里等)若被污染,serve 一个不同的 wheel,当前没有
   任何机制能发现。

现状里**已有的优势**(方案要保留):
- 依赖装进 per-plugin `.deps/`,插件之间不共享 site-packages。
- bundled Python 3.13 运行时(python-build-standalone)→ **所有终端用户跑
  同一 Python 版本**,极大简化跨版本锁定问题。
- pip 不传 `--index-url` → 用户镜像配置(`PIP_INDEX_URL` / `pip.conf`)
  自动生效。**方案必须保留这一点**。
- 依赖声明**已经用 PEP 508 environment markers**(如
  `winrt-runtime>=2.0; sys_platform == 'win32'`),跨平台依赖已表达好。

## 2. 目标 / 非目标

### 目标

- 每个声明了依赖的插件,其依赖闭包(顶层 + 全部 transitive)被锁定到
  **精确版本 + sha256 hash**,安装时用 `pip install --require-hashes` 强制
  校验完整性。
- 上游投毒 / 镜像污染 → hash 不匹配 → 安装失败 → 攻击被挡。
- 镜像源继续可用(hash 是文件内容的,与 index URL 正交)。
- 锁与依赖声明的一致性由 CI 强制(drift-check),复用我们在 API-types
  Phase 0 验证过的"重新生成 + git diff --exit-code"模式。

### 非目标 (YAGNI)

- ❌ **不做运行时沙箱 / 子进程隔离**。供应链锁定与进程隔离正交;后者是
  独立工作,且当前不做(见会话结论)。
- ❌ **不引入 `registry.json` 签名 / `official` 权威化**。那是子项目 #2。
- ❌ **不引入 capability 声明 / consent UI**。那是子项目 #3。本 spec 只在
  sideload 无锁拒装时弹一个**最小**提示,不构建完整 consent 框架。
- ❌ **不硬编码 PyPI index**。保留用户镜像配置流通。
- ❌ **不改 bundled Python 运行时版本管理**。锁定目标固定为 3.13。

## 3. 架构(跨两个 repo)

```
┌─────────────────────────── magi-plugins repo ───────────────────────────┐
│ plugins/<id>/plugin.toml          (人类可读, 松范围 + markers, 作者写)   │
│        │                                                                  │
│        ▼  scripts/lock-deps.py  (新增, 调 uv pip compile --universal)     │
│        │                                                                  │
│        ▼                                                                  │
│ plugins/<id>/requirements.lock    (机器生成, ==精确版本 + 多平台 hash)    │
│        │                                                                  │
│        ▼  .github/workflows/ci.yml  (新增, drift-check)                   │
│           重跑 lock-deps.py + git diff --exit-code                        │
└──────────────────────────────────────────────────────────────────────────┘
                                   │ git clone --sparse + copy
                                   ▼
┌─────────────────────────────── magi repo ────────────────────────────────┐
│ backend/src/magi/plugins/installation.py                                  │
│   _build_dependency_install_command:                                      │
│     pip install --target .deps --no-user                                  │
│       --require-hashes -r <plugin>/requirements.lock   ← 改这里           │
│   sideload 无锁策略: 有依赖但无 requirements.lock → 默认拒装              │
│       + developer-mode 逃生口                                             │
└──────────────────────────────────────────────────────────────────────────┘
```

**职责边界**:
- **magi-plugins**:生成锁、提交锁、CI 守护锁与声明一致。
- **magi**:安装时强制 `--require-hashes`;处理无锁 sideload 的拒装/逃生口。

## 4. 组件

### 4.1 `magi-plugins/scripts/lock-deps.py`(新增)

读每个 `plugins/<id>/plugin.toml` 的 `[plugin].dependencies`(及
`[plugin].dependencies` 风格的其它键,如部分插件用 `default_settings` 内联——
以 manifest 的顶层 `dependencies` 为准),对**声明了依赖的插件**调用:

```bash
uv pip compile \
    --universal \
    --generate-hashes \
    --python-version 3.13 \
    --output-file plugins/<id>/requirements.lock \
    -                       # 依赖从 stdin 喂入
```

要点:
- `--universal`:一次解析覆盖 macos + win(尊重 `sys_platform` markers),
  产出含多平台 wheel hash 的单一锁文件。
- `--generate-hashes`:每个 pin 带 sha256。
- `--python-version 3.13`:对齐 bundled 运行时。
- 依赖通过 stdin 传入(从 plugin.toml 的 `dependencies` 列表拼成
  requirements 文本),**不引入单独的 `requirements.in`**——plugin.toml 仍是
  唯一人类来源。
- 无依赖的插件(如 git_activity 只用 stdlib + git subprocess):不生成锁文件。

CLI 形态:
- `python scripts/lock-deps.py`           — 重新生成所有插件的锁
- `python scripts/lock-deps.py <id>`      — 只重生成一个
- `python scripts/lock-deps.py --check`   — 不写文件,只检查是否需要更新
  (CI 用;退出码非零 = 有 drift)

### 4.2 `plugins/<id>/requirements.lock`(机器生成,提交进 git)

示例(`calendar_plugin`):

```
# This file is auto-generated by scripts/lock-deps.py. Do not edit.
# Source: plugins/calendar_plugin/plugin.toml [plugin].dependencies
pyobjc-core==10.3.1 \
    --hash=sha256:aaaa... \
    --hash=sha256:bbbb...
pyobjc-framework-Cocoa==10.3.1 \
    --hash=sha256:cccc...
pyobjc-framework-EventKit==10.3.1 \
    --hash=sha256:dddd...
```

提交进 git 的理由(同 API-types 决策):PR review 能直接看到依赖闭包变化;
clone 即可装,不需要本地跑 uv;CI diff 简单。

### 4.3 `magi-plugins/.github/workflows/ci.yml`(新增,该仓首个 workflow)

```yaml
name: CI
on:
  pull_request:
  push:
    branches: [main]

jobs:
  lockfiles-in-sync:
    name: Plugin lockfiles in sync with manifests
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
      - uses: actions/setup-python@v6
        with:
          python-version: "3.13"
      - name: Install uv
        run: pip install uv
      - name: Regenerate lockfiles
        run: python scripts/lock-deps.py
      - name: Assert lockfiles committed up to date
        run: |
          if ! git diff --exit-code -- 'plugins/*/requirements.lock'; then
            echo "::error::One or more plugin requirements.lock files are stale."
            echo "Run 'python scripts/lock-deps.py' locally and commit the result."
            exit 1
          fi
  registry-in-sync:
    name: registry.json in sync with manifests
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
      - uses: actions/setup-python@v6
        with:
          python-version: "3.13"
      - name: Regenerate registry
        run: python scripts/build-registry.py
      - name: Assert registry committed up to date
        run: |
          if ! git diff --exit-code -- registry.json; then
            echo "::error::registry.json is stale. Run scripts/build-registry.py and commit."
            exit 1
          fi
```

注:`uv pip compile` 在 ubuntu 上做 `--universal` 解析,产出的锁含 macos +
win 两平台 wheel 的 hash,与运行 runner 的平台无关(universal 解析不需要在
目标平台上跑)。`registry-in-sync` job 顺手补上(agents.md 已要求手动重生成
registry,但没 CI 守护,属于既有缺口)——**这一项独立于供应链锁定,作为同批
CI 引入的便车,不扩大本 spec 安全范围**。

### 4.4 `magi/backend/src/magi/plugins/installation.py`(改安装命令 + 无锁策略)

`_build_dependency_install_command` 改为:

```python
def _build_dependency_install_command(
    lock_path: Path,
    deps_dir: Path,
    *,
    quiet: bool,
) -> list[str]:
    cmd = [
        _resolve_dependency_python_executable(),
        "-m", "pip", "install",
        "--target", str(deps_dir),
        "--no-user",
        "--disable-pip-version-check",
        "--require-hashes",
        "-r", str(lock_path),
    ]
    if quiet:
        cmd.insert(cmd.index("-r"), "--quiet")
    return cmd
```

`_install_dependencies` 的调用方逻辑改为:
1. 插件无 `dependencies` 声明 → 跳过(现状)。
2. 插件有 `dependencies` 且 `requirements.lock` 存在 → 用上面的 hash-enforced
   安装。
3. 插件有 `dependencies` 但**无 `requirements.lock`**:
   - 默认 → **拒装**,抛错并提示"This plugin declares dependencies but ships
     no integrity-locked requirements.lock. Refusing to install unverified
     dependencies."
   - 若 `MAGI_ALLOW_UNLOCKED_PLUGIN_DEPS=1`(或 settings 里的 developer-mode
     开关)→ 退回当前松范围安装,并 `logger.warning` 记一条审计日志。

**仍然不传 `--index-url`** → 用户镜像配置继续生效。`--require-hashes` 与
任意 index 兼容(hash 校验文件内容,与来源正交)。

### 4.5 developer-mode 逃生口

- 后端读 `MAGI_ALLOW_UNLOCKED_PLUGIN_DEPS` 环境变量,或一个持久化的
  developer setting(若已有 developer/advanced settings 区,挂在那里;否则
  环境变量即可,本 spec 不强求新建 UI)。
- 默认关闭。开启时每次无锁安装写审计日志。
- 官方 marketplace 插件不受影响(CI 保证有锁)。

## 5. 数据流

### 5.1 插件作者改依赖(magi-plugins)

1. 改 `plugins/<id>/plugin.toml` 的 `dependencies`。
2. 本地跑 `python scripts/lock-deps.py <id>`(需要本地有 uv;CONTRIBUTING
   注明 `pip install uv`)。
3. `requirements.lock` 更新,连同 plugin.toml 一起提交 PR。
4. CI 重跑 `lock-deps.py --check` + `git diff` → 漏跑则红。

### 5.2 用户安装插件(magi App)

1. marketplace `git clone --sparse` 取插件目录(含 `requirements.lock`)。
2. 后端 `pip install --require-hashes -r requirements.lock --target .deps`,
   走用户镜像。
3. 任一 hash 不匹配(投毒/污染镜像)→ 安装失败,插件不落地。

### 5.3 用户 sideload 插件包(设置里上传 archive)

1. 解包,读 plugin.toml。
2. 有依赖 + 有锁 → 同 5.2。
3. 有依赖 + 无锁 → 默认拒装(除非 developer-mode)。

## 6. 迁移(一次性)

当前 6 个声明依赖的插件需补锁:`calendar_plugin`、`screen_time`、
`system_media`、`screenshot_timeline`、`telegram`、`weixin`。

一次性:在 magi-plugins 仓跑 `python scripts/lock-deps.py`,提交全部
`requirements.lock`。这是单个 PR,低风险(纯新增文件)。

## 7. 测试 / 验证

### magi-plugins 侧

- `lock-deps.py` 对 6 个含依赖插件生成的锁,`--require-hashes` 安装在
  macos + win 各自能装成(至少在本地 macos 验证,win 靠 CI 或后续手测)。
- `lock-deps.py --check` 在锁与 manifest 一致时退出 0,不一致时非零。
- CI drift job 在故意改 plugin.toml 不重生成锁时变红。

### magi 侧

- 单元测试 `_build_dependency_install_command` 产出含 `--require-hashes -r
  <lock>` 且不含 `--index-url`。
- 安装一个真实带锁插件(calendar)→ `.deps/` 落地正确版本。
- 篡改锁里某个 hash → 安装失败(模拟投毒被挡)。
- 无锁 + 有依赖插件 → 默认拒装;设 `MAGI_ALLOW_UNLOCKED_PLUGIN_DEPS=1` →
  退回松安装 + 警告日志。
- 现有 magi-gateway / backend 测试不回归。

## 8. 已知风险与缓解

### 8.1 uv `--universal` 锁可能含目标平台装不上的 marker 行

`--universal` 锁含 macos + win 的 wheel。pip 装时按当前平台的 environment
marker 过滤。`--require-hashes` 模式下,pip 仍只装匹配当前平台的包。
**缓解**:迁移时在 macos 实测一个 win-only 依赖插件(system_media)的锁能否
在 macos 正确跳过 win 包;CI 加 win runner 做反向验证(可作为后续增强,不阻塞
首个 PR)。

### 8.2 镜像缺失锁定的精确版本

若用户镜像太旧、没同步到锁定版本,安装失败。**缓解**:这是版本可用性问题,
非 hash 特有;镜像通常数小时内同步;错误信息提示"try the official PyPI index
or wait for your mirror to sync"。

### 8.3 uv 解析结果与 pip 安装的细微差异

uv 解析依赖,pip 执行安装。理论上两者解析器不同,但 `--require-hashes` 锁死了
精确版本+hash,pip 没有解析自由度,只能装锁里写的。**缓解**:锁是精确 pin,
pip 仅做"下载+校验+解压",无解析分歧空间。

### 8.4 transitive 依赖的平台特异性 wheel hash 爆炸

某些包(pyobjc 全家)transitive 很多,锁文件会变长。**缓解**:可接受,锁文件
是文本、可读、PR diff 清晰。

### 8.5 developer-mode 逃生口被滥用

用户被诱导开 `MAGI_ALLOW_UNLOCKED_PLUGIN_DEPS` 装恶意插件。**缓解**:默认关、
每次警告日志、文档明确风险。这是"知情的开发者选择",非默认路径。

## 9. 开放问题

无。工具(uv)、无锁 sideload 策略(默认拒装 + 逃生口)均已收敛。

## 10. 与兄弟子项目的关系

- **本项目(供应链锁定)**:解决"依赖被投毒"。
- **子项目 #2(registry 权威 + 签名)**:解决"插件自报 official 伪装"。
  `build-registry.py:42` 现在直接抄自报字段——那是它的现场。本项目顺手加的
  `registry-in-sync` CI job 是它的地基。
- **子项目 #3(capability 声明 + consent UI)**:解决"看不出插件实际行为 +
  用户知情同意"。本项目 sideload 拒装的最小提示,将来并入它的 consent 框架。
- **进程隔离/沙箱(挂起)**:解决"插件搞挂主应用 + 运行时越权"。等真实信号
  (telemetry segfault / 第三方规模)再启动。
